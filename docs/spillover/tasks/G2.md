G2 (admission margin: model it, configure it)

Context: this is Doubleword's Dynamo fork. The fork has an admission gate in the frontend (lib/runtime/src/component/admission.rs and its callers in lib/runtime/src/pipeline/network/egress/push_router.rs and lib/llm/src/kv_router/push_router.rs): each worker's queue estimate = its reported num_waiting_reqs + admissions since that report; workers at or over the margin are excluded from selection ("steering") unless every live worker is saturated, and the gate may evict lower-priority requests or return 529. Margins come from DYN_ADMISSION_QUEUE_MARGIN / DYN_ADMISSION_QUEUE_MARGIN_OVERRIDES (per model). Proxy workers never report num_waiting_reqs, so they are never enforced. For spillover models the margin on hosted workers is a hard cutoff that drops a busy hosted worker before our policy can keep cached conversations on it, so it should sit above the policy's own failover point. Read docs/spillover/PLAN.md and docs/spillover/tuning.md.
